## Problem Statement

Оператор реестра получает технические характеристики сооружений в виде «боевых»
государственных Excel-файлов (и иногда CSV): многолистовых, с многоуровневой объединённой
шапкой, мусорными строками-заголовками, разными названиями колонок от разных филиалов.
Сейчас занести эти данные в реестр можно только вручную через `/admin/` — поле за полем,
строка за строкой. Это медленно, чревато опечатками, не масштабируется на сотни строк и
не защищает от создания дублей одного и того же сооружения из разных листов/выгрузок.

## Solution

Оператор загружает файл (Excel или CSV) в один endpoint и сразу получает отчёт о том, что
импортировалось. Система сама определяет тип сооружения по заголовку файла, понимает кривую
многоуровневую шапку, сопоставляет колонки файла с полями реестра через LLM (который видит
только имена колонок и сэмплы, но не сами данные — значения раскладывает код), а затем
дедуплицирует записи по водоисточнику + названию + году ввода + пространственной близости
координат. Полные совпадения пропускаются, расхождения попадают в отчёт без записи в базу,
несопоставленные колонки и проблемы перечисляются как предупреждения. Оператор видит
сводку: сколько создано, сколько пропущено как дубли, какие конфликты и предупреждения.

## User Stories

1. Как оператор реестра, я хочу загрузить Excel-файл с характеристиками каналов, чтобы не вносить сотни строк вручную.
2. Как оператор реестра, я хочу загрузить CSV-файл, чтобы импортировать данные из выгрузок без листов.
3. Как оператор реестра, я хочу, чтобы система сама определила тип сооружения по строке-заголовку файла («…всех каналов…»), чтобы не выбирать его руками.
4. Как оператор реестра, я хочу, чтобы система разобрала многоуровневую объединённую шапку, чтобы колонки вида «До реконструкции / Всего протяжённость, км» корректно сопоставились с полями.
5. Как оператор реестра, я хочу, чтобы система пропускала мусорные строки (заголовки таблицы, группы объектов, строки-номера колонок), чтобы в базу попали только реальные сооружения.
6. Как оператор реестра, я хочу, чтобы система обработала все листы Excel-файла, чтобы данные с разных листов не терялись.
7. Как оператор реестра, я хочу, чтобы повторяющиеся между листами сооружения не создавали дублей в базе, чтобы реестр оставался чистым.
8. Как оператор реестра, я хочу, чтобы при расхождении значений у одного и того же сооружения система НЕ записывала противоречивые данные, а сообщала о конфликте, чтобы я мог разобраться вручную.
9. Как оператор реестра, я хочу видеть, у какого поля, на каком листе и какие значения разошлись, чтобы быстро находить причину конфликта.
10. Как оператор реестра, я хочу, чтобы система дедуплицировала не только внутри файла, но и против уже существующих в базе записей, чтобы повторная загрузка не плодила дубли.
11. Как оператор реестра, я хочу, чтобы идентичность сооружения определялась по водоисточнику + названию + году ввода + координатам в радиусе 100 м, чтобы близкие по имени, но разные объекты не склеивались.
12. Как оператор реестра, я хочу, чтобы система предупреждала, когда у строки нет ключа для склейки (нет названия или координат), чтобы я понимал, почему запись создана как отдельная.
13. Как оператор реестра, я хочу, чтобы LLM не выдумывал значения, а только сопоставлял колонки с полями, чтобы данные в реестре были достоверными.
14. Как оператор реестра, я хочу, чтобы колонки, которые не удалось сопоставить ни с одним полем, перечислялись в отчёте, чтобы я видел, что осталось неучтённым.
15. Как оператор реестра, я хочу, чтобы отсутствующие в файле значения оставались пустыми, а не заполнялись догадками, чтобы не вносить ложные данные.
16. Как оператор реестра, я хочу, чтобы координаты (широта/долгота) из файла записывались в геополе сооружения, чтобы объект отображался на карте.
17. Как оператор реестра, я хочу получить синхронный ответ с полным отчётом сразу после загрузки, чтобы не опрашивать статус задачи.
18. Как оператор реестра, я хочу видеть в отчёте количество созданных записей, чтобы убедиться, что импорт прошёл.
19. Как оператор реестра, я хочу видеть количество пропущенных дублей, чтобы понимать, что система отфильтровала повторы.
20. Как оператор реестра, я хочу, чтобы для каждого типа сооружения (канал, шлюз, водозабор, насосная станция, плотина/дамба, гидропост) заполнялись его специфические поля, чтобы импорт работал не только для каналов.
21. Как оператор реестра, я хочу, чтобы общие поля (рег. №, район, % износа, тех. состояние, год на баланс, КПД и т.д.) сопоставлялись независимо от типа, чтобы база заполнялась полно.
22. Как оператор реестра, я хочу, чтобы при создании сооружения корректно создавались и базовая запись, и запись подкласса (multi-table inheritance), чтобы объект был валиден в реестре.
23. Как разработчик, я хочу, чтобы LLM-граница была изолированным портом, чтобы её можно было подменить в тестах и при смене провайдера.
24. Как разработчик, я хочу, чтобы доменная логика (ключ идентичности, детект конфликтов) не зависела от Django/IO, чтобы её можно было тестировать изолированно.
25. Как оператор реестра, я хочу осмысленную ошибку при загрузке неподдерживаемого формата (например SQL), чтобы понимать, что так нельзя.
26. Как оператор реестра, я хочу понятную ошибку, если файл повреждён или пуст, чтобы не гадать о причине.

## Implementation Decisions

- **Новое приложение `ingestion`** (чистая архитектура), а не размазывание логики по существующим app: слои `domain` (чистая логика без Django/IO) → `application` (use-case) → `infrastructure` (парсеры, LLM, persistence) → `interfaces` (view/urls/serializers). Регистрируется в `INSTALLED_APPS`; маршрут добавляется в корневой `urls.py`.

- **API-контракт.** `POST /api/import/`, `multipart/form-data` с файлом. Синхронный. Доступ открытый, без аутентификации (хакатон, не прод — ADR-0003). Ответ — отчёт об импорте:
  ```json
  {
    "created": 142,
    "skipped_duplicates": 38,
    "conflicts": [
      {"key": "...", "field": "efficiency_fact", "existing": 0.73, "incoming": 0.70, "sheet": "Корректировка"}
    ],
    "warnings": ["..."],
    "unmapped_columns": ["..."]
  }
  ```

- **Форматы.** Excel (`.xls`/`.xlsx`) и CSV. SQL не реализуется — на SQL-файл возвращать осмысленную ошибку (ADR-0003).

- **Парсинг шапки (гибрид, ADR-0003).** Код детерминированно находит блок шапки, **протягивает значения объединённых ячеек** (merge fill) и собирает флэт-имена колонок (уровни через разделитель). К каждой колонке прикладываются 1–3 сэмпла данных. Мусорные строки (заголовок таблицы, «Группа объектов N», строка с номерами колонок) отбрасываются.

- **Маппинг через LLM (ADR-0001).** LLM получает флэт-имена колонок + сэмплы + каталог целевых полей и возвращает структуру `{ facility_type, mapping: { col_index: field } }`. **LLM не видит значения строк** — их раскладывает детерминированный код. Промпт явно запрещает выдумывать значения; неизвестные колонки не маппятся (→ `unmapped_columns`); отсутствующие данные остаются пустыми. `facility_type` определяется тем же вызовом по строке-заголовку и набору колонок.

- **LLM-клиент.** Пакет `openrouter` (`from openrouter import OpenRouter`), модель `openrouter/auto`, ключ `OPENROUTER_API_KEY` из `.env`. Адаптер изолирован в `infrastructure/llm` как порт; при нестабильности пакета — fallback на OpenAI-совместимый клиент без изменения доменной логики (ADR-0003).

- **Обработка листов и склейка (ADR-0002).** Анализируются все листы Excel (каждый со своей шапкой и своим LLM-вызовом). CSV = один плоский лист. Ключ идентичности: `water_source` + `name` + `year_built` **И** пространственная близость координат ≤ 100 м (PostGIS `ST_DWithin` по `location`, SRID 4326). Дедуп идёт и внутри файла (между листами), и против существующих записей БД.

- **Разрешение совпадений/конфликтов (ADR-0002).** Полное совпадение → не пишем (`skipped_duplicates`). Конфликт (ключ совпал, значения разошлись) → запись **не пишем**, добавляем в `conflicts`. Нет ключа (нет названия/координат) → создаём как отдельную запись + `warning`.

- **Запись.** Репозиторий создаёт базовую запись `BaseHydroFacility` и запись подкласса (`Canal`/`Sluice`/`WaterIntake`/`PumpingStation`/`DamsAndDykes`/`HydroPost`) согласно multi-table inheritance. Координаты `широта/долгота` → `PointField`.

- **Каталог целевых полей** (вход в промпт) — фиксируется в `domain/field_catalog.py`: общие поля `BaseHydroFacility` + поля каждого подкласса (полный список — в [file-import-design.md](../file-import-design.md)).

## Testing Decisions

- **Что считаем хорошим тестом:** проверяем только внешнее поведение через высокий шов — отправляем реальный файл-фикстуру в endpoint и утверждаем JSON-отчёт и итоговые строки в тестовой БД. Не тестируем приватные функции, имена флэт-колонок, внутренние структуры — только наблюдаемый результат.

- **Основной шов — HTTP endpoint `POST /api/import/`** (Django test client). Один шов прогоняет весь конвейер по-настоящему: парсинг Excel/CSV, merge fill, раскладка, резолвер идентичности, PostGIS-дедуп (`ST_DWithin`), запись base+подкласс.

- **Единственный мок — LLM-порт.** В тестах LLM-адаптер подменяется фейком, возвращающим детерминированную карту `{facility_type, mapping}`. Это делает тесты герметичными, бесплатными и стабильными. Всё остальное (включая реальный PostGIS в тестовой БД) не мокается.

- **Тестируемые модули:** `interfaces` (endpoint) как точка входа; косвенно — `application`/`domain`/`infrastructure` через него. Доменные правила идентичности/конфликтов покрываются преимущественно через сценарии endpoint'а.

- **Ключевые сценарии:** успешный импорт каналов из многолистового `.xls`; пропуск дубля при полном совпадении между листами; конфликт (расхождение КПД) → запись не создана, попала в `conflicts`; дедуп против уже существующей записи в БД; строка без координат/названия → создана + `warning`; несопоставленная колонка → в `unmapped_columns`; CSV как один плоский лист; SQL-файл → осмысленная ошибка.

- **Прайор-арт:** в проекте тесты пока пустые Django-заглушки (`*/tests.py`). Новый набор тестов в `ingestion` задаёт прайор-арт. Учесть: GeoDjango/PostGIS требует пространственной тестовой БД; фикстуры `.xls`/`.csv` хранить рядом с тестами. Реальный пример структуры — `датасет(1).xls` в корне репо.

## Out of Scope

- SQL-файлы (исключены явно).
- Асинхронная обработка / очереди (Celery), опрос статуса задачи.
- Аутентификация и авторизация endpoint'а.
- Геокодирование по названию района/водоисточника при отсутствии координат.
- Пакетная загрузка нескольких файлов / архивов (`.zip`).
- UI загрузки (только endpoint; вызов из admin/формы — отдельная задача).
- Редактирование/обновление существующих записей при конфликте (только отчёт, разрешение — вручную).
- Откат/транзакционность всего импорта как единого целого сверх стандартной построчной записи.
