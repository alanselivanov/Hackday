# ADR-0001 — LLM маппит схему (заголовки), а не данные

**Статус:** принято · 2026-06-25

## Контекст
Спецификация (`file_parser.md`) буквально предлагает слать сырой JSON со строками данных
в LLM, чтобы он разложил их по нашим полям. Файлы содержат ~450 строк × 3 листа.

## Решение
LLM получает **только заголовки колонок** (флэт-имена) + **1–3 сэмпла данных** под
каждой колонкой + каталог целевых полей, и возвращает **карту маппинга**
`индекс колонки → поле модели` плюс определённый `facility_type`. Значения всех строк
раскладывает по этой карте **детерминированный код**, без участия LLM.

## Обоснование
- Один дешёвый LLM-вызов на лист вместо ~1350 строк.
- LLM физически не видит числовые значения → не может их «исправить»/выдумать.
  Требование спеки «не выдумывать значения» выполняется конструктивно.
- Карту можно залогировать и показать в отчёте (аудируемость).

## Последствия
- Нужен надёжный парсинг шапки в флэт-имена (см. [ADR-0002](0002-multi-sheet-merge-and-identity.md)
  и обзор архитектуры).
- Каталог целевых полей с описаниями становится частью кода (вход в промпт).

## Отклонено
- **A — LLM маппит каждую строку:** дорого, медленно, риск тихого искажения чисел.
- **C — гибрид с построчным fallback:** избыточная сложность для хакатона.
