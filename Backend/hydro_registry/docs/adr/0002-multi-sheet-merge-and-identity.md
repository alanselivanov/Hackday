# ADR-0002 — Многолистовая склейка, ключ идентичности и обработка конфликтов

**Статус:** принято · 2026-06-25

## Контекст
Excel-файл содержит несколько листов с разными наборами колонок (в примере: `каналы`,
`Лист1`, `Корректировка`), частично описывающих одни и те же объекты. Нужно избегать
дублей в БД, но не терять данные и сигналить о расхождениях.

## Решение

### Обработка листов
Анализируются **все** листы Excel. Каждый лист маппится отдельно (своя шапка → свой
LLM-вызов). CSV = один плоский лист, без межлистовой логики.

### Ключ идентичности
Две записи считаются одним объектом, если совпадают:
`water_source` + `name` + `year_built`
**И** координаты находятся в радиусе ≤ **100 м** друг от друга
(PostGIS `ST_DWithin` по `location`, SRID 4326).

Проверка идёт **и внутри файла** (между листами), **и против существующих записей в БД**.

### Разрешение
- **Полное совпадение** (ключ + значения сходятся) → в БД не пишем, `skipped_duplicates++`.
- **Конфликт** (ключ совпал, значения расходятся) → запись **не пишем**, добавляем в
  `conflicts` с указанием поля, существующего/входящего значения и листа-источника.
- **Нет ключа** (напр. на листе нет названия или координат) → запись создаётся как
  отдельная + `warning` «нет ключа для склейки».

## Обоснование
- Композитный ключ + пространственная проверка устойчивы к переезду порядковых `№`
  между выгрузками — играют на сильную сторону PostGIS.
- «Не писать при конфликте» (выбор 6b=c) безопаснее автослияния: человек разрулит по отчёту.

## Последствия
- Координаты обязательны для надёжной склейки; их отсутствие деградирует до warning.
- Нужен пространственный запрос на каждую кандидат-запись (приемлемо при синхронном импорте).

## Отклонено
- Склейка только по `№` строки — хрупко между файлами.
- Склейка только по названию — лист `каналы` без названий не сцепить.
- Автослияние значений при конфликте — риск тихой потери правды.
