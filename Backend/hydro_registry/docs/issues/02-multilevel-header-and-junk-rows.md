# [ingestion] Грязная многоуровневая шапка и отброс мусорных строк

> **Триаж:** `ready-for-agent`
> **Источник:** [PRD](../prd/file-import-endpoint.md)
> (ADR [0003](../adr/0003-formats-and-endpoint-contract.md))

## What to build

Усиление парсера до реальных госфайлов. Парсер находит блок шапки (в примере — строки
3–6), **протягивает значения объединённых ячеек** (merge fill) по вертикали и
горизонтали и собирает осмысленные флэт-имена колонок, склеивая уровни иерархии через
разделитель (напр. `«До реконструкции / Всего протяжённость, км»`). Эти флэт-имена вместе
с 1–3 сэмплами данных под каждой колонкой уходят в LLM-порт.

Мусорные строки отбрасываются и не попадают в реестр: строка-заголовок таблицы
(«Таблица 3», «Технические характеристики всех каналов…»), строки-разделители групп
(«Группа объектов N», «В республиканской собственности…»), строка с номерами колонок
(`1.0  2.0  3.0 …`).

Проверяется на реальном `датасет(1).xls` (лист `Лист1` — самый полный).

## Acceptance criteria

- [ ] Блок шапки определяется автоматически, не хардкодом номера строки.
- [ ] Значения объединённых ячеек протягиваются; каждая колонка получает полное флэт-имя из всех уровней.
- [ ] Мусорные строки (заголовок таблицы, группы объектов, строка номеров колонок) отбрасываются.
- [ ] В LLM-порт уходят флэт-имена + сэмплы данных по колонкам.
- [ ] Тест: импорт реальной фикстуры с многоуровневой шапкой создаёт корректные записи каналов; мусорные строки в БД отсутствуют.
