# [ingestion] Резолвер идентичности: пропуск дублей и отчёт о конфликтах

> **Триаж:** `ready-for-agent`
> **Источник:** [PRD](../prd/file-import-endpoint.md)
> (ADR [0002](../adr/0002-multi-sheet-merge-and-identity.md))

## What to build

Дедупликация против существующих записей реестра при импорте (один лист). Перед записью
строка сопоставляется с существующими записями по ключу идентичности:
`water_source` + `name` + `year_built` **И** пространственная близость координат ≤ 100 м
(PostGIS `ST_DWithin` по `location`, SRID 4326).

Разрешение:
- **Полное совпадение** (ключ совпал, значения сходятся) → запись не создаётся,
  увеличивается `skipped_duplicates`.
- **Конфликт** (ключ совпал, значения расходятся) → запись **не создаётся**, добавляется
  в `conflicts` с указанием поля, существующего и входящего значения, листа-источника.

Отчёт расширяется полями `skipped_duplicates` (число) и `conflicts` (список).

## Acceptance criteria

- [ ] Ключ идентичности строится из `water_source` + `name` + `year_built` + близости координат ≤ 100 м (`ST_DWithin`).
- [ ] Полное совпадение с существующей записью → не пишем, `skipped_duplicates` растёт.
- [ ] Конфликт значений → запись не создаётся, попадает в `conflicts` с полем/значениями/листом.
- [ ] Отчёт содержит `skipped_duplicates` и `conflicts`.
- [ ] Логика ключа/конфликта реализована в доменном слое без зависимостей от Django/IO.
- [ ] Тесты: повторный импорт совпадающей записи → пропуск; импорт записи с расхождением (напр. КПД) → конфликт, запись не создана (реальный PostGIS в тестовой БД).
